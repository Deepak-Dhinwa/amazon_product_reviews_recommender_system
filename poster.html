Office Products Recommender

Shoppers leave a few stars and disappear. A small matrix factorization still ranks what they have not bought.

Surprise SVDStreamlitRecall@10
  1. 01 · FilterAmazon office-products ratings, kept where the user and the item both appear often enough to learn from.
  2. 02 · TrySeveral ways to fill the empty matrix: classic SVD, a truncated one, a hybrid, a neural net.
  3. 03 · KeepSurprise SVD is the one that ranks unseen items. The others stay in the notes.
  4. 04 · ServeType a reviewer id. Items they already reviewed are hidden. Ten predictions remain.

Question

  • Given only star ratings, what should this shopper see next?
  • Most people review a handful of items, so almost every cell in the matrix is empty.

Why this path

  • With so few ratings per person, the useful signal is “people who liked this also liked that,” which is what SVD stores.
  • A content model barely sees the shopper. It was tried, and the collaborative fit is what the page loads.

What held

0.84SVD error on the 1–5 star scale
0.94Recall@10, items the user did rate
~370kreviews in the filtered table

Reading the result

  • RMSE 0.84 means a predicted star is usually within about a star of the true one, on a scale that only runs from 1 to 5.
  • Recall@10 means the items a person actually liked tend to land in the ten the model would have shown.
  • That number is on shoppers who already have ratings. Someone new, with an empty history, is a different problem.

A real output

User AN2FZ6SBNYDDQ already-reviewed items dropped 10 items returned predicted stars near the top of 1–5

The page prints item id and predicted rating, one line each.

How the tries compared

  • The served file is svd_model.pkl.
  • Other factorizations were fit on the same table and did not rank as well, so they are documented and not loaded.

Still open. Cold-start shoppers and a neural ranker on this same sparse table. The app stays on the fit that already ranks.
